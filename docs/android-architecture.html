1. Overview

DAVE is a computer agent first — Linux-first, with macOS and Windows supported. Android is an add-on: the same repo runs inside Termux on the phone, and iOS is not planned. Nothing Android-specific happens off the phone: the extension returns immediately unless process.platform === "android" or $PREFIX contains com.termux (isAndroid()).

Three pillars hold it up:

  • Native file tools with one reach rule. Eight tools in .pi/lib/android-tools.ts, all gated by .pi/lib/android-guard.ts: Termux home is always reachable, plus at most one shared-storage folder the user mounts.
  • A model. Either llama.cpp's llama-server on the phone itself (provider dave-local), or any OpenAI-compatible endpoint — including an app on the same phone (loopback) or a remote one.
  • Shell scripts for setup and lifecycle. scripts/android-setup.sh installs and configures; scripts/dave-android.sh starts, serves, stops and reports.

3. Setup flow — scripts/android-setup.sh

Flags: --provider local|custom answers the model question (needed without a terminal); --model REPO:Q, --ctx, --threads, --port only apply to local (the script warns and ignores them otherwise); --update-pi also refreshes pi. With --provider custom, ENDPOINT_NAME, ENDPOINT_URL, ENDPOINT_API_KEY and ENDPOINT_MODEL answer connect.mjs's questions.

4. Start and stop — scripts/dave-android.sh

The exact server command: llama-server -hf <repo:quant> --jinja --host 127.0.0.1 --port <port> -c <ctx> -t <threads> --temp 0.1 --top-k 50 --repeat-penalty 1.05. It binds loopback only. While waiting, the script polls /health every 3 seconds (a note every 15s), and fails fast — log tail included — if the process dies.

5. Extension boot and hooks — .pi/extensions/android.ts

The command /dave:android is registered the same way; see Commands for what it dispatches.

6. The reach rule — .pi/lib/android-guard.ts

Before any check, the path is expanded and resolved: expand() maps the aliases above, path.resolve anchors it against the working folder, and realish() realpaths the deepest existing ancestor with the missing tail re-appended — so new files work, and .. or a symlink like ~/storage/shared cannot escape.

Check order inside guard()

The third box runs only for writes, and checks containment in both directions — so a folder that contains a protected path can't be moved out and back.

bash

Shell commands get a best-effort text check only: blockedShellRef() refuses any command that mentions .dave/android, and runs each shared-storage-looking reference (~/storage/*, $EXTERNAL_STORAGE, /sdcard, /storage/…) through guard(). A determined command can get around a text check; the skill file tells the model not to try.

7. A tool call, end to end

So a DAVE tool is checked twice from different directions: the repo-wide guard decides whether the call may happen at all, and the reach rule decides where the path may point.

11. Design decisions

One reach rule for everything

DAVE's eight tools and pi's built-ins go through the same guard(). Two enforcement points, one rule: there is no second policy to keep in sync.

Real paths, not string matching

realish() resolves the deepest existing ancestor, so .. and symlinks such as ~/storage/shared can't launder an outside path into an allowed one.

One folder, never all of shared storage

validateMount() refuses shared storage itself and anything outside it, and requires a readable+writable directory. The mount is the only door into shared storage.

Delete is off, and still asks

allowDelete defaults false; even when on, guard.jsonc keeps delete_path at ask. Two switches a model can't flip for itself.

The model can't change its own permissions

~/.dave/android, ~/.pi/agent, the extension and lib folders, guard.jsonc and mcp.json are write-protected — including any folder that contains them, so move-out/move-back doesn't work either.

The reach note repeats every turn

Small models lose track of the mount. before_agent_start re-states the exact paths, the mount's aliases, and that searching home doesn't reach it.

Caps sized for small models

200 entries, maxReadBytes (setup writes min(ctx, 65536), default 8192), 100 matches, 300-char lines. Enough to work with, not enough to swamp a small context.

Scripts own lifecycle; the extension stays thin

Starting, stopping, pidfiles, wake locks and logs all live in dave-android.sh; /dave:android model … just calls it. One implementation, two front ends.

The endpoint option reuses connect.mjs

--custom is the same code path desktop setup uses for the studio: the provider lands in models.json the same way, and setup only records the choice.

Managed pi, not npm

pi comes from its own installer (pi.dev/install.sh) into ~/.pi/agent; npm can hand out an older release, so an npm pi is replaced.

Q4_0 tiers

Liquid recommends Q4_0 on phones and llama.cpp repacks it into Arm kernels. Some repos also ship a -QAD-Q4_0 file, but -hf repo:Q4_0 resolves deterministically to the plain file — llama.cpp takes the first regex match in HF's lexically sorted listing, and -Q4_0. sorts before -QAD-.

Known limits

  • The bash check is a text check — best effort, documented as such in docs/android.md.
  • Not yet verified on a device (same list as the docs): that Termux's llama-cpp package can download with -hf, and whether the largest tier fits in free memory on a 12GB phone.
  • The fetch MCP server fails at startup on the phone — it needs uvx, which setup doesn't install.

See docs/android.md for the user-facing setup, permissions and troubleshooting list.
